# Motivation

对action token提出了三个要求:
1. 高压缩率
2. 完全可解码性
3. 从左到右因果有序的token空间

所谓“Ordering”或者“因果有序”, 指的是在AutoRegressive生成的时候, 先生成粗糙的token, 然后随着token生成增多, 让轨迹变的越来越精细:
![[2602.04215v1.pdf#page=1&rect=193,476,393,507]]
同时, 某一步生成出来的token前缀，能够被解码器稳定地“解码成一个有效可执行的连续action chunk”

- AR Bin(通过Bin切分, 类似 [[RT-2]], [[2406.09246|OpenVLA]], ...):
	- 不满足“高压缩”, token序列长度随时间和action dim线性增长, 训练/推理困难
	- 满足“完全可解码”, bin是固定规则的离散分箱映射, 能够直接解码
	- 不满足“Ordering”, bin token仅仅是action dim$\times$time的串行化, 与“由粗到细”没有关系
- AR QueST(使用[[2309.15505|FSQ]]将连续的action chunk离散化成token, 然后进行自回归生成):
	- 满足“高压缩”, 将一个chunk的action压缩成一个token
	- 满足“完全可解码”, 因为每一个token都可以被解码成一个action
	- 不满足“Ordering”, 因为每一个token是一个chunk, 没有逐步细化的过程
- AR FAST(使用[[2501.09747|FAST]]进行encode, 然后使用自回归生成token):
	- 满足“高压缩”, 这个也是把一个chunk压缩到一个token里面
	- 不满足“完全可解码”, 因为FAST使用了[[Hands-On Large Model Engineering#Lecture 04|BPE]]进行压缩, 但BPE每一个token解码的结果(每一个token对应的频域系数)不是等长的, 因此也无法直接解码
	- 满足“Ordering”, 将生成的token按照顺序拼接得到从低频到高频的顺序, 以此获得因果有序
- DP ([[Diffusion]]和[[2210.02747|Flow Matching]]作为action head, 逐步refine动作)
	- 这种方式不是离散token得方法, 因此无法使用本文提出的三个要求.
	- 但是可以类比:
		- 不适用“高压缩率”, 因为这不是token, 是直接连续生成
		- 天然满足完全可解码性, 任意一个step都是一个action, 只是这些step的noise含量不同
		- 与“Ordering”类似但形式不同, 这个是“从粗糙逐步细化”的过程

# Methods

![[2602.04215v1.pdf#page=4&rect=44,582,569,750]]

使用 [[1706.03762|Transformer]] 的 Auto Encoder 架构, 同时引入一些新的设计:
1. 引入一组可学习的token(被称为Registers), 用于和action进行信息融合, 提取时空信息
2. 使用 [[2309.15505|FSQ]] 对Register的输出进行编码
3. 使用 [[2602.04215v1.pdf#page=4&selection=606,4,607,17|Nested Dropout]] 丢弃后面的输出, 随机采样一个 $K\in[1,H_l]$ ($H_l$是register的dim), 只保留前 $K$ 个token, 强迫前面的token学习全局信息, 后面的token补全细节; 使用[[2602.04215v1.pdf#page=5&selection=10,0,10,19|因果注意力机制]], 让前面的token只能看到前面的信息

这里的 [[2602.04215v1.pdf#page=4&selection=606,4,607,17|Nested Dropout]] 指的是, 按顺序丢弃后面的输出(与传统随机丢弃的dropout相比). 由于前面的token比后面的token更容易“存活”, 因此强迫encoder在编码的时候, 把整体的趋势写入前面的token中, 然后后面的token负责细节部分

> 这类似残差学习, 先学习一个主干, 然后让后面的其他token来补全细节部分

> 还类似频域, 让低频重建长程的意图, 让高频补全残差

完整的训练流程:
1. 将action经过MLP映射到latent space
2. 将latent action和registers进行拼接, 送入transformer进行encode
3. 将registers的输出单独提取出来, 经过FSQ量化
4. 使用Nested Dropout, 随机丢弃后面的几个token
5. 把保留下来的token后面拼接mask, 作为K/V送入Transformer Decoder, 让Position Embeddings作为Q去交互, 最终输出decoded latent action
